# Building the release candidate

For the Nexus test variant, run `build_nexus.py --source REVIEWED_CORE --output NEW_OUTPUT_FOLDER --app REVIEWED_DESKTOP_BUILD --plugin REVIEWED_GAMEPLAY_DLL --version 0.4.26 --gameplay 0.3.16`. This compiles SetupLauncher.cs using Windows' .NET Framework compiler, reuses the reviewed manifest, unpacks Python's internal standard-library ZIP, and generates a ZIP with no nested archives. It performs integrity checks but does not authorize publication or settle third-party licensing. NexusMods.cs provides manual ZIP import; Nexus online dependency/update resolution is not implemented. Publication of 0.4.26 is paused for author testing.

The staging builder expects a workspace containing `work/rune` (this source project), `outputs/RuneCompanion` (reviewed runtime/model inputs), and writes `outputs/RuneRelease`. Place the `packaging` folder of a source export at `work/rune/release` for this workflow. It never reads the user's bridge, account or mod-profile folders.

When reconstructing this layout from the public export, keep `src`, `audio`, `tests`, `tools` and `blueprint-library` beneath `work/rune`. Copy the exported `docs` into `work/rune/release/docs`, and copy the root `README.md`, `.gitignore`, `LICENSE` and `LINKING-EXCEPTION.md` into `work/rune/release/public`. Run `fetch_notices.py` with network access to populate available upstream notices in `release/licenses`; review its error records rather than treating missing licenses as cleared.

Publish `src/Voice/RuneVoice.csproj` into `work/rune/release/app` using .NET 8. Build `src/Mod/RuneCompanion.csproj` against your licensed game references and copy its RuneCompanion.dll into `work/rune/release/plugin`. Supply the official Python 3.12.10 Windows x64 embedded ZIP as `python-3.12.10.zip`. The builder selects only current audio packages, Kokoro, Whisper small.en, .NET, the freshly built Rune plugin, blueprints, and explicitly selected model packs from the reviewed staging input.

Run `build_release.py core`, then `build_release.py packs`. Make any authored corrections using `refresh_candidate.py`, and finish with `build_release.py seal`. A new core build must start in an empty output folder; it refuses to merge with a previous candidate. Export source with `export_source.py --output NEW_FOLDER --deny PRIVATE_TERM`, repeating the deny option for locally known private names. The terms themselves are not written to the report.

Never supply a live installation as a release archive directly. Keep source exports and release archives separate from private development history and diagnostics. Review the third-party license inventory, release gates, signatures and resulting privacy report before upload.

Tests: `test_packaging.py` validates corruption rejection, archive path validation, update/rollback and failed-copy recovery using temporary fixtures. `Start Rune.ps1 -SmokeTest` runs the installed core against loopback ports 12439/12441/12442, generates a synthetic local-brain reply and renders the welcome screen. It never starts Valheim or asks for live microphone capture. The ordinary runtime uses 11439/11441/11442. Alternate ports prove service isolation, not hardware or OS independence.

For distributable binaries, force a Release rebuild with `-t:Rebuild -p:DebugType=None -p:DebugSymbols=false`, then publish the rebuilt desktop with `--no-build`. Merely changing debug properties on an incremental publish can retain old binaries and embedded private PDB paths. Scan the final DLL/EXE bytes as well as the source export before sealing the manifest.

For the compact variant, run `build_compact.py --source REVIEWED_OFFLINE_CANDIDATE --output NEW_COMPACT_FOLDER`. It moves the unchanged Whisper and Kokoro model files into a hash-checked speech-core pack, adds an optional setup choice, and permits core-only startup with microphone and spoken replies initially disabled. Place the speech ZIP beside the extracted compact folder. Other authors' mods remain excluded.

## Online original-source installer

The preferred small installer is now built with `build_online.py --source REVIEWED_OFFLINE_CANDIDATE --output NEW_ONLINE_FOLDER`. The source is used only as an allowlisted source of Rune's own files and notices. Third-party runtime/model folders are excluded. Setup uses the locked `online-downloads.json`; it does not require the old manual model ZIPs. Python, both base and Desktop .NET runtimes, wheels, and selected models download from their publishers.

`lock_online_sources.py` is a build-time metadata tool. It needs `packaging` and access to official publisher URLs. It recreates the lock from the reviewed installed versions, including original model file hashes. Do not regenerate it merely to get the latest packages: changed dependencies need new validation. Download-time checks use SHA-256 or the publisher's SHA-512. The pure Python ANTLR source package is extracted without running setup.py; other Python dependencies use publisher wheels.

Keep `online-assets` and `online-downloads.json` beside the packaging sources when reconstructing the source export. The UI script must be emitted as UTF-8 with BOM for Windows PowerShell 5.1. Text is WPF interface text, separate from the original generated artwork.

Run `test_online_installer.py`, then the actual setup into a new folder. `test_online_speech.py INSTALLATION OUTPUT` generates and transcribes a synthetic line without playback or microphone access. If a restricted development token prevents upstream eSpeak temporary DLL creation, record that limitation and test under an ordinary token; do not modify the upstream DLL to conceal it.

Current local validation covers the default downloads, app startup, voice synthesis and recognition. The optional Qwen/Chatterbox source endpoints and hashes were checked; a complete new installation of every large optional stack was not exercised on this run because of available disk space. Existing offline expressive tests do not establish a fresh online install. No upload, second-PC test, Nexus staff clearance or final legal clearance is implied.

Installer revision r2 fixes destination feedback: selecting the extracted installer directory is rejected before bootstrapping with a specific explanation. Desktop/Documents roots resolve to a RuneFellowship child folder. Custom empty Desktop folders remain valid. `Setup Worker.ps1` is shared by the UI and the nine `test_setup_worker.ps1` checks; it persists each attempt's output to the separate download cache and returns a structured success/error result so a generic job error cannot conceal the reason. Logs are local and excluded from release/source packages.

Installer revision r3 includes `Service Ports.ps1` beside the launcher. A per-installation mutex prevents duplicate launchers for the same folder; occupied default ports cause selection of a free loopback group without stopping another installation. Real listener tests and isolated app startup with an occupied preferred port passed. Only the three authored runtime Python scripts are retained in the core; third-party Python modules download from their sources. The resulting test ZIP is 24,832,169 bytes. Publication authorization is separate from Nexus network-tool review.

## In-app updates (desktop 0.4.27)

Build and test the desktop first, with DebugType=None and DebugSymbols=false. Assemble and seal a clean online installer core containing both app/RuneVoice.dll and the matching payload/BepInEx/plugins/RuneCompanion/RuneCompanion.dll. Include Start Rune.ps1 and Update Recovery.ps1. Never use a live installation as packaging input.

Run build_update.py --core CLEAN_INSTALLER/Rune --output OUTPUT. Upload Rune-Update-VERSION.zip and Rune-Update-VERSION.zip.sha256 to the official rokley-hub/RuneFellowship GitHub release tagged vVERSION, together with the matching installer and source. Beta clients include beta releases; stable clients exclude prereleases. The updater only offers newer releases that contain both named assets on that exact repository. Installer-only releases are not offered. This first updater release requires a one-time installer upgrade for users on 0.4.26.

The update contains authored app files and Rune's own plugin; optional speech/runtime/model downloads are excluded. Keep dependency requirements compatible with the installed runtimes for this schema. A runtime migration needs a new installer flow before offering the release to this updater. External manager profiles still update their game plugin through that manager; only Rune-owned profiles are updated by the desktop worker.

Checks: RuneVoice --update-checks OUTPUT exercises policy, hashes, path validation, profile/data preservation and rollback. test_update_recovery.ps1 -FixtureRoot ISOLATED_FOLDER verifies interrupted transaction recovery under Windows PowerShell 5. The installed startup script holds the per-installation mutex and stops its owned services before recovery. Never delete incomplete update backups.
